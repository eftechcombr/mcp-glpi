# How is the codebase organized?

## Project Structure

```
.
├── src/
│   ├── index.ts           # MCP server: tool catalogue, dispatch, resources, CLI entry
│   ├── glpi-client.ts     # Typed domain client (tickets, assets, users, ...)
│   ├── http.ts            # OAuth2 + HTTP layer (retry, timeout, GlpiError)
│   ├── search.ts          # RSQL search engine + ITEMTYPE_PATH_MAP
│   ├── search-options.ts  # /listSearchOptions cache (1h TTL)
│   ├── sessions.ts        # SessionManager for multi-tenant HTTP mode
│   └── http-server.ts     # Streamable HTTP transport (Bun.serve)
├── test/
│   ├── http.test.ts       # Auth, retries, API version, errors, timeouts
│   ├── search.test.ts     # Pagination, count, field resolution, path mapping
│   └── sessions.test.ts   # Session isolation, status, eviction, teardown
├── scripts/
│   └── smoke.ts           # Live integration smoke test
├── .context/              # AI development scaffolding (not published)
├── dist/                  # Compiled CommonJS output (generated by tsc)
├── Dockerfile             # Multi-stage Bun image
├── docker-compose.yml     # Local / smoke-test / hosted setups
├── .github/workflows/     # Docker image publish workflow
├── README.md              # User docs: configuration, tool catalogue, Docker
├── CHANGELOG.md           # Release history
├── AGENTS.md              # Agent collaboration conventions
└── package.json           # Scripts, deps, published files
```

## Request Flow

1. A client calls an MCP tool (stdio or Streamable HTTP).
2. `src/index.ts` validates arguments (zod for ticket writes), resolves the
   session's `GlpiClient`, and dispatches to a domain method.
3. `GlpiClient` performs REST calls through `GlpiHttp`, which owns OAuth2
   tokens, retries, timeouts, and structured errors.
4. List/search calls go through `GlpiSearch`, which builds RSQL filters and
   uses `SearchOptionsCache` to translate field ids/names.
5. Results are normalised (labels, resolved foreign keys) and returned as MCP
   text content.

## Publishing Boundaries

`package.json` publishes only `dist/`, `README.md`, and `LICENSE`. `.context/`,
`src/`, and `test/` stay in the repository and are excluded from the npm
tarball. `prepublishOnly` runs `bun run build`.
